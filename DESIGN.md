# Bulls and Cows — устройство проекта

Документ описывает реализованный код: структуры данных, алгоритмы, их сложность
и применение принципов чистого кода.

## 1. Структуры данных и алгоритмы

### Состояние раунда и история

Игровые типы определены в [game.type.ts](./src/game/game.type.ts).

| Структура          | Данные и назначение                                                             |
| ------------------ | ------------------------------------------------------------------------------- |
| `GameSettings`     | Основание и длина секрета; фиксируются при старте раунда                        |
| `GameState`        | Настройки, секрет, история, статус `playing` / `won` и время старта             |
| `GuessAttempt`     | Введённая строка и подсказка `bullsCount` / `cowsCount`                         |
| `GameResult`       | Настройки, количество принятых попыток и длительность в миллисекундах           |
| `LeaderboardEntry` | Идентификатор раунда и `GameResult`; секрет и история в рекорды не записываются |

Секрет и попытка представлены строками. Это сохраняет ведущие нули и позволяет
одинаково работать с цифрами BIN, OCT, DEC и HEX. Числовое представление потеряло бы
различие между `0123` и `123`.

История — упорядоченный массив. В [makeGuess](./src/game/lifecycle/make-guess.ts)
новая попытка добавляется через `[...history, attempt]`, а состояние создаётся
через spread. Предыдущие массивы, записи и объект состояния не изменяются.
Отклонённая попытка возвращает исходный объект состояния. Повтор определяется
сравнением строк без учёта регистра, поэтому `A2F0` и `a2f0` — одна попытка.

Поля игровых объектов объявлены `readonly`. Это ограничение TypeScript, а не
автоматическая заморозка объектов во время исполнения. Иммутабельность обеспечена
самими операциями обновления и проверяется тестами, в том числе на замороженных
входных данных.

[startGame](./src/game/lifecycle/start-game.ts) проверяет настройки и создаёт
пустую историю. [finishGame](./src/game/lifecycle/finish-game.ts) принимает только
выигранный раунд, вычисляет число попыток из длины истории и вычитает время старта
из переданного времени завершения. Некорректные временные метки отклоняются.

Состояние интерфейса [AppState](./src/view/state/app-state.ts) хранится отдельно.
Оно содержит язык, тему, текущий раунд, черновик ввода и сообщения. Контроллеры
изменяют это состояние интерфейса, но заменяют игровой `GameState` результатом
Lifecycle. При смене языка или темы раунд не генерируется заново.

### Генерация секрета

[generateSecret](./src/game/core/generate-secret.ts) использует частичное
перемешивание Фишера — Йетса:

1. Создаёт массив допустимых цифр выбранного основания.
2. Для позиции `i` выбирает индекс от `i` до конца ещё не выбранной части.
3. Меняет выбранную цифру с цифрой в позиции `i`.
4. После `length` шагов соединяет первые `length` цифр в строку.

Цифры выбираются без повторений; ноль участвует наравне с остальными цифрами.
Перемешивается локальный массив, входные данные не изменяются.

Источник случайности передаётся параметром и должен возвращать число в `[0, 1)`.
По умолчанию используется `Math.random`. В приложении передаётся
[randomSource](./src/view/utils/random-source.ts): линейный конгруэнтный генератор
с начальным seed из Web Crypto. Это генератор с внутренним состоянием, а не
криптографический алгоритм. В тестах применяется управляемый источник случайности;
сама передача функции не делает произвольный источник случайности чистым.

### Валидация попытки

[createDigitValidator](./src/game/core/create-digit-validator.ts) создаёт массив
допустимых цифр и возвращает предикат, замыкающий этот массив. Предикат принимает
один символ, нормализует регистр и проверяет принадлежность алфавиту через `includes`.

[isValidGuess](./src/game/core/is-valid-guess.ts) проверяет основание, длину,
допустимость всех символов через `every` и отсутствие повторов через `Set`.
Та же фабрика используется для фильтрации ввода в
[guess-form.ts](./src/view/ui/elements/guess-form.ts). Фильтрация в UI улучшает ввод,
а повторная проверка в Lifecycle защищает обработку отправленной попытки.

### Подсчёт быков и коров

[evaluateGuess](./src/game/core/evaluate-guess.ts) рассчитан на допустимые строки
одинаковой длины с уникальными цифрами; в игровом сценарии это обеспечивает
валидация перед сравнением.

1. Обе строки переводятся в нижний регистр и преобразуются в массивы символов.
2. Из цифр секрета создаётся `Set` для проверки принадлежности.
3. `filter` считает совпадения символа и позиции — быков.
4. Второй `filter` считает цифры попытки, присутствующие в секрете.
5. Коровы равны общему числу совпавших цифр за вычетом быков.

Например, для секрета `1234` и попытки `1243` получается 2 быка и 2 коровы.
Уникальность цифр позволяет не вводить частотные таблицы и не учитывать одну
цифру несколько раз.

Текущее API возвращает `{ bullsCount, cowsCount }`. В задании указаны имена
`{ bulls, cows }`; это остаётся расхождением контракта, а не исключением из требований.

### Количество возможных секретов

[countPossibleSecrets](./src/game/core/count-possible-secrets.ts) считает размещения
без повторений: `P(b, n) = b! / (b - n)!`.

Используется рекуррентная формула:

```text
P(b, 0) = 1
P(b, 1) = b
P(b, n) = b × P(b - 1, n - 1)
```

Длина больше основания и некорректные аргументы дают `0`. Ведущий ноль разрешён,
поэтому отдельное вычитание вариантов с нулём не требуется. Например, BIN/2
даёт два секрета: `01` и `10`.

Промежуточные результаты сохраняются в `Map<string, number>` с ключом
`length:base`. Повторный запрос возвращается из кэша. Кэш живёт до перезагрузки
модуля; его изменение не меняет результат вычисления для тех же аргументов.
Подсчёт вызывается при отображении и изменении настроек.

### Лидерборд и хранение

[updateLeaderboard](./src/game/leaderboard/update-leaderboard.ts) создаёт копию
массива, не добавляет повторный идентификатор раунда, сортирует по количеству
попыток, затем по длительности и оставляет первые 10 записей. При полном равенстве
сохраняется порядок поступления. Используется общий список; в UI у каждой записи
отображаются основание и длина секрета.

[local-storage.ts](./src/view/infrastructure/local-storage.ts) отвечает только
за JSON и операции хранения. [Сервис лидерборда](./src/view/service/leaderboard-storage.service.ts)
владеет ключом, проверяет структуру загруженных данных и восстанавливает топ-10.
Ошибки рекордов отображаются в интерфейсе и не блокируют игру. Язык и тема
сохраняются отдельными сервисами под собственными ключами.

## 2. Сложность алгоритмов

Обозначения: `n` — длина секрета и допустимой попытки, `b` — основание,
`K` — число записей в кэше. Для `Set` и `Map` принимается средняя стоимость
доступа `O(1)`, для арифметики — постоянная стоимость в допустимом диапазоне игры.
Память учитывает временные массивы, результат и стек рекурсии.

| Функция                | Время                       | Дополнительная память                      | Обоснование                                                                                       |
| ---------------------- | --------------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| `generateSecret`       | `O(b + n)`                  | `O(b + n)`, то есть `O(b)` при `n ≤ b`     | Массив алфавита из `b` цифр, `n` обменов и создание строки из `n` цифр                            |
| `evaluateGuess`        | `O(n)`                      | `O(n)`                                     | Нормализация, массивы, создание `Set` и два линейных прохода через `filter`                       |
| `isValidGuess`         | `O(b + n × b)`              | `O(b + n)`                                 | Фабрика создаёт `b` цифр; `every` вызывает линейный `includes` до `n` раз; `Set` обрабатывает `n` |
| `countPossibleSecrets` | Без попадания в кэш: `O(n)` | Стек `O(n)` и до `O(n)` новых записей кэша | На каждом шаге длина уменьшается на один; одна проверка кэша и одно умножение                     |
| `countPossibleSecrets` | Попадание в кэш: `O(1)`     | `O(1)` на вызов; общий кэш занимает `O(K)` | Значение возвращается без рекурсивного пересчёта                                                  |

В интерфейсе `b` принимает только 2, 8, 10 или 16, поэтому при фиксированном
основании `isValidGuess` линейна по длине. Запись `O(b + n × b)` отдельно показывает
стоимость текущего `includes`, не приписывая ему постоянную сложность.
Ранние отказы по длине и основанию могут завершаться быстрее указанных оценок.

## 3. Принципы чистого кода

| Принцип                              | Где и как применён                                                                                                                                                             |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Разделение ответственности           | [Core](./src/game/core/) содержит алгоритмы; [Lifecycle](./src/game/lifecycle/) — переходы раунда; [контроллеры](./src/view/controllers/) связывают их с интерфейсом           |
| Явные зависимости и тестируемость    | `generateSecret` получает random; `startGame` и `finishGame` получают время. Тесты не зависят от текущего времени и случайной последовательности                               |
| Иммутабельные обновления             | `makeGuess` создаёт новый объект и массив истории. `updateLeaderboard` сортирует копию, сохраняя входной массив                                                                |
| Одно правило в одном месте           | [isValidGameSettings](./src/game/validation/is-valid-game-settings.ts) используется при старте и загрузке рекордов; [конфиг](./src/game/game.config.ts) задаёт игровые пределы |
| Проверка данных на границе           | Сервис лидерборда принимает JSON как `unknown` и проверяет поля до использования. Статические типы не заменяют эту проверку                                                    |
| Ранние возвраты и явные исходы       | `makeGuess` отдельно отклоняет завершённый раунд, некорректную и повторную попытки; `MakeGuessResult` различает принятие и отказ через `status`                                |
| Содержательные имена                 | `secretSequence`, `attemptsHistory`, `elapsedTime` и `countPossibleSecrets` обозначают назначение данных и операции                                                            |
| Отделение представления от состояния | [app.ts](./src/view/app.ts) собирает страницы; [AppState](./src/view/state/app-state.ts) сохраняет раунд при перерисовке; страницы создают DOM без `innerHTML`                 |
| Общие тексты и оформление            | [Переводчик](./src/view/i18n/translator.ts) хранит словари EN/RU, [style.css](./src/style.css) использует CSS-переменные для светлой и тёмной темы                             |

Тесты расположены рядом с реализациями. Они проверяют результаты, граничные
случаи, неизменность входов и управляемые ошибки хранения. Наличие этого документа
не заменяет проверку сборки и ручной сценарий на опубликованной версии.
